# 关重件更换流程图（mom-key-component-change）

> 本文件只放流程图（用户操作流程 / 状态机 / 接口时序 / 数据流 / 代码级细节）。
> 约束与规则见 `../AGENT.md`（§8、§12）；接口字段协议见 `关重件更换INF.md`。
> 接口一律用语义名，对照 Portal 函数名见 §三 表头。

## 一、用户操作流程

### 流程 A：正常采集

```
① 订单号/VIN 输入框：输入/扫码自动转大写 → 回车（或点 🔍）
        ↓  接口：查询订单信息 → 查询关重件信息
② 同一 VIN 下若同时存在生产订单与改制订单：顶部显示订单切换按钮（订单号搜索默认命中单、VIN 搜索默认改制单），页面只展示所选订单的卡片，可随时切换；卡片不再带订单徽章；
   需采集数量沿用现状；需解绑数量 = 待解绑清单条数（有待解绑才显示该行）
        ↓  自动聚焦「物料二维码」输入框
③ 扫关重件二维码（格式 `物料编码|供应商|序列号[:数量[:其它…]]`，数量之后的多余段忽略；输入/扫码自动转大写）→ 回车（或点 🔍 / 📷）
        ↓  页面校验：格式 → 是否集合内关重件 → 是否已采集 → 物料类型是否还有待解绑 → 归属订单（未满量单：改制优先 → 生产单；都满走更换）→ 位置（见 §二）→ 是否替换（isReplace）
        ↓  该物料类型还有待解绑 → 跳解绑页（只列该类型），解完自动返回，回车继续采集
        ↓  例：A 需采集、B 需解绑且同类型（编码可不同）→ 扫 A 先跳去解绑 B，B 解完自动返回后再采集 A
        ↓  永磁体同步电机：采集时序号配置不明确才弹位置选择；其他关重件取配置序号、不弹窗
④ 采集成功：Toast「采集成功」，列表与数量自动刷新，输入框清空并保持聚焦（报文 `wipOrderNo`/`wipOrderType`/`vin` 为归属订单）
        ↓
⑤ 重复 ③ 直到「需采集数量」显示为 0
⑥ 点「完成」→ 确认 → 会话清空，可开始下一单
```

### 流程 B：改制订单解绑（视图2）

```
① 待解绑由 removeSnList 驱动：扫码命中「该物料类型还有待解绑」时自动跳解绑页（按该类型过滤）；
   也可点「需解绑数量」行的「解绑」按钮进入（不带类型，显示全部）
② 解绑页只列当前过滤类型的待解绑旧件（行内订单号带类型）；列表来自查询关重件信息的 removeSnList，不单独请求
③ 点某行「移除」→ 确认 → 移除关重件{ 行内订单, vin, serialNo } → 旧件被解绑，Toast「移除成功」
        ↓  刷新订单数据（removeSnList、卡片）
        ↓  当前过滤类型待解绑归 0 → **自动回主页**（输入框二维码保留）；否则重渲染解绑页
④ 重复 ③ 直到该类型解绑完成（不同物料类型互不阻塞）
⑤ 也可随时点「返回」→ 回主页（刷新数据）
```

### 流程 C：换件（视图3）

```
① 扫到物料，isReplace=是（生产单该物料已采完；改制单该物料已采完，或未采完但同 VIN 生产单该物料已有已采 SN）
        ↓  永磁体同步电机必须弹位置选择（操作员现场指定前/后）；其他关重件不弹窗
② 视图3 列出待更换旧件（按本次新件的物料编码 + 序号过滤：前电机只回前电机旧件；按录入时间倒序）
   查询范围：生产单只查该生产单该物料；改制单查改制 + 同 VIN 生产单该物料
③ 选一条旧件 → 点「更换」→ 确认
        ↓  页面执行：移除关重件 → 保存新关重件（materialSeq = 所选 "1"/"2"，其它情况 ""）→ 刷新关重件信息
④ 成功：Toast「更换成功」→ 自动回主页，数量保持不超过需采总数
```

### 流程 D：VIN更换（视图4）

```
① 点右上角「VIN更换」按钮（贴顶右对齐，四个视图下都可点）
        ↓  进入视图4：订单号预填当前订单号（单订单取该单，多订单取改制单）；旧VIN/新VIN/出厂编码清空；提示信息为前端固定文案
        ↓  查询 VIN 信息{ wipOrderNo } → 回填 旧VIN（标签）、旧出厂编码（预填出厂编码输入框供修改）（无当前订单则不自动查）
② 订单号输入框：输入/扫码自动转大写；回车 / 🔍 按钮 → 重新查询 VIN 信息；📷 按钮 → OpenCamera 扫码后自动查询
③ 新VIN、出厂编码输入框：输入/扫码自动转大写；📷 按钮扫码录入（也可手输）
④ 点「确认」→ 去除新VIN/出厂编码中的全部空格并回写输入框 → 校验：
        订单号非空 → 旧VIN 已查到 → 新VIN 非空且 17 位 → 出厂编码 非空且 16 位 → 新VIN 与出厂编码后五位一致
        ↓  保存 VIN{ wipOrderNo, oldVin, newVin, oldFactoryCode, factoryCode }（旧值来自查询，新值来自本次录入）
        ↓  成功：Toast「VIN更换成功」→ 同步本地订单 `vin = newVin`（订单 VIN 即 serialNo 字段承载的车辆 VIN）→ 自动回视图1（刷新关重件信息）
⑤ 点「返回」→ 回视图1（不调接口）
```

> 该按钮同样受 `BUTTON_SWITCH.vinChange` 显示/权限开关管辖（AGENT.md §8.11），开关项 `vinChange`；视图4 内每个按钮也有独立开关项。

### 并发与数据新鲜度（多人同时操作）

> 页面数据是「查询时快照 + 操作后刷新」；多人同时操作时，别人的变更只能靠刷新/后端校验发现。

```
A 失败即刷新：Save / Remove / 删除序列号失败 → 静默刷新关重件信息 + 错误 Toast
B 进页刷新：进解绑页 / 替换页前，距上次加载 > 5s 则先刷新
             （解绑页刷新后该类型无待解绑 → 提示并停留主页）
C 自动刷新：空闲每 30s、窗口聚焦、页面重新可见时，若距上次加载 > 30s 且在主页、无弹窗、未提交 → 静默刷新
D 切单刷新：切换展示订单时，若数据已过期（> 30s）→ 静默刷新
```

> 冲突的最终判定在后端：`Save` / `Remove` 以数据库当前状态校验（重复序列号、旧件已移除、物料不存在、数量超限等），
> 失败返回明确 `code`/`msg`，页面按 A 刷新并提示重试。

### 无权限按钮的点击提示

| 按钮 | 开关项 | `permitted: false` 时点击 |
|---|---|---|
| 序列号行内「删除」 | `deleteSerial` | Toast「没有权限，请扫码更换」，不执行删除 |
| 右上角「VIN更换」 | `vinChange` | Toast「没有权限」，不进入 VIN更换 页面 |

> 这两项用 `.disabled` 类 + `aria-disabled` 做视觉禁用（开关项配了 `deniedMessage`），**不加原生 `disabled`**——原生 disabled 不派发 click，提示无从触发；其余按钮仍是原生 disabled。规则见 AGENT.md §8.11。

### 临时隐藏的按钮（物料二维码不支持扫码）

| 按钮 | 开关项 | 现状 |
|---|---|---|
| 物料二维码 📷 扫码按钮 | `scanMaterial` | `visible: false` 默认隐藏 |

> 原因：物料二维码是**复合串**（`物料编码\|供应商\|序列号[:数量[:其它]]`），而扫码 API 会对扫码内容做处理、**只返回最后一个值**，无法原样返回整串；订单号/VIN/新VIN/出厂编码都是单值，扫码 API 返回最后一个值即原值，因此它们的 📷 按钮保持显示。
> 隐藏只作用于 📷 按钮本身：物料二维码输入框、🔍 搜索按钮与 **PDA 键入扫码链路**均不受影响（回车/搜索/扫码三个业务入口中「扫码」由 PDA 键入承担）。待扫码 API 支持原样返回后，将开关置回 `visible: true` 即恢复。

## 二、状态机

### 视图状态机

> 图中「刷新数据」＝重新查询关重件信息，更新卡片与数量标签（含需解绑数量）；回到视图1 收尾统一为「刷新数据 + `clearMaterialInput()` + 聚焦输入框」。

```
                 ┌──────────────────────────────┐
                 │ 视图1 更换主页                │
                 │ (.key-component-check-view)   │
                 └───┬───────────┬───────────┬───┘
      解绑按钮(改制且还需解绑)│  替换判定/      │ 完成(二次确认)
                           │   替换=是        │
                           ▼                  ▼
              ┌────────────────────┐   ┌────────────────────┐
              │ 视图2 移除页        │   │ 视图3 更换页        │
              │ 返回→视图1+刷新数据 │   │ 返回→(半完成则确认) │
              └────────────────────┘   │ →视图1+刷新数据     │
                                       └─────────┬──────────┘
                                       更换成功→视图1+刷新数据

> 视图2：**当前过滤类型的待解绑清零**后自动返回视图1（`leaveRemoveView()` 保留二维码）；点「返回」则走常规返回（`backToCheckView()` → 视图1 + 刷新数据）。不同物料类型互不阻塞。

  任意视图下点右上角悬浮「VIN更换」→ 视图4 VIN更换页
        (.key-component-vin-change-view)
        返回 → 视图1（不调接口）；确认成功 → 视图1 + 刷新数据
```

### 两条更换入口（差异只在"谁触发更换判定"）

| 入口 | 触发条件 | `materialSeq` 来源 | 首次 `pendingScan` 写入点 |
|---|---|---|---|
| **替换判定** | 生产单：该物料已采 ≥ Σ`materialQty`；改制单：该物料已采完，或未采完但同 VIN 生产单该物料有已采 SN | 永磁体同步电机更换必弹位置选择；其他关重件取配置序号 | `startMaterialChange()` |
| **正常采集** | 以上条件不满足 | 同上 | `checkAndSave()`（`Save` 的 `oldGenealogyID` 传空） |

### 订单集合（订单号搜索 1 张；VIN 搜索改制 + 生产，无主次）

```
查询订单信息 → orderList（订单号/VIN 都先按 VIN 归组，返回该 VIN 下所有订单；前端按订单数逐单查询关重件信息；展示按所选订单过滤，默认：订单号搜索→命中单，VIN 搜索→改制单）
查询关重件信息 → 对集合内每张单各调一次（单订单返回），前端合并并打归属
视图1 渲染：只展示当前选中订单的卡片（按物料编码分组，不再带订单徽章），序列号按「订单 + materialID」归属
采集归属：未满量的单（改制优先 → 生产单）→ 都满走更换（改制单）
报文：Save 的 wipOrderNo、wipOrderType、vin 与订单物料字段取「归属订单」
需采集数量：当前选中订单 `max(0, Σ该单需采 − 配置内已采 − 待解绑)`（非配置物料的历史序列号不计入已采）
需解绑数量：removeSnList.length（有待解绑才显示；扫码按类型跳转、解绑页按类型过滤）
```

> 卡片数量 = 该单该物料 `已采 / Σ materialQty`；**改制单的 `materialQty` 可为负数**（如 `-1`，卡片显示 `0/-1`），解绑后后端把该组件数量回到 `0`，页面刷新后显示 `0/0`（页面不截断负数）。
>
> **物料描述/类型等主数据只从 `keyComponentList` 取**（按 `materialID` 或 `materialNo` 匹配）：卡片、解绑页描述、按类型卡控/过滤都用这一份；`removeSnList`/待更换明细只带标识字段。

> 改制单的「待解绑」来自**同 VIN 对应生产订单**上、与改制单物料类型匹配的已采 SN（后端解析并返回，行内订单为生产订单）；解绑执行的是生产订单的旧件。

> 兼容：后端未返回 `orderList` 时前端包成单元素数组；`removeSnList` 缺失视为空（无解绑）。

### `pendingScan` 生命周期（换件的核心）

```
handleMaterialCheck()
   ├─ isReplace=否 → checkAndSave(): pendingScan = 本次扫描 → Save(oldGenealogyID="")
   │        ├─ 失败 → pendingScan = null（可重新扫）
   │        └─ 成功 → pendingScan = null → 刷新关重件信息
   └─ 已满量 → startMaterialChange(): pendingScan 为空才写入 → enterChangeView()
                                        （pendingScan 非空说明已在换件决策中，直接忽略重复触发）
视图3:
   移除关重件 成功 → changedOldGenealogyId / changedOldSerialNo 落库到 state，行标记「重试保存」
   保存新关重件 成功 → pendingScan / changedOldGenealogyId / changedOldSerialNo 全部清空
   保存新关重件 失败 → 三者保留（半完成态），允许「重试保存」
   返回（半完成）→ 二次确认 → leaveChangeState() 清空三者
```

### 位置弹窗与序号来源

```
序号只有一个来源：位置弹窗人工选择，或页面自动分配（无其他入口）
位置弹窗只对永磁体同步电机（materialType = "永磁体同步电机"）发生：
   采集：序号配置不明确（两条配置不是恰好 "1"+"2"）或前后位置都已采集 → 弹窗
         配置明确且有未采集位置 → 自动分配，不弹窗
   更换：必须弹窗，由操作员现场指定被替换的位置
其他关重件：一律不弹窗 → 直接取配置序号（单条取该条，多条取首条）
上报归一：null/undefined → ""；其它配置值（如 "3"）原样上报
进入视图3 → 作为 查询待更换明细 的 materialSeq 入参（"" 表示不按位置过滤）
```

## 三、接口调用时序

> 语义名 ↔ Portal 注入函数对照（字段级协议见 `关重件更换INF.md`）

| 语义名 | window 函数 | taskType |
|---|---|---|
| 查询订单信息 | `KeyComponentChange_GetWipOrderNoInfo` | `GetWipOrderNoInfo` |
| 查询关重件信息 | `KeyComponentChange_GetKeyComponentInfo` | `GetKeyComponentInfo` |
| 移除关重件 | `KeyComponentChange_Remove` | `Remove` |
| 查询待移除明细 | `KeyComponentChange_GetRemoveKeyComponentInfo` | `GetRemoveKeyComponentInfo`（页面已不使用） |
| 查询待更换明细 | `KeyComponentChange_GetChangeKeyComponentInfo` | `GetChangeKeyComponentInfo`（页面已不使用） |
| 保存扫描件（正常采集 / 替换） | `KeyComponentChange_Save` | `Save` |
| 查询 VIN 信息 | `KeyComponentChange_GetVinInfo` | `GetVinInfo` |
| 保存 VIN | `KeyComponentChange_SaveVin` | `SaveVin` |

### 序列 A：查单 + 正常采集

```
操作员                页面                        Portal 注入函数
  │  输入/扫码订单（自动转大写）─▶ queryOrderInfo()
  │                     ├─ 解析：纯数字→wipOrderNo；17位非纯数字→vin；其它→wipOrderNo
  │                     ├─ showLoading("查询订单中...")
  │                     ├─ 查询订单信息 ─────────▶ KeyComponentChange_GetWipOrderNoInfo
  │                     │   （序号守卫：过期响应丢弃）
  │                     ├─ hideLoading
  │                     ├─ 失败→Toast「查询失败」+ 画面保持上一次订单集合（数据自洽）
  │                     └─ 成功→state.orders = data.orderList（旧结构包成单元素数组）
  │                          ├─ clearKeyComponentState()   ← 换单即清空上一次关重件数据
  │                          ├─ 订单号标签并列集合内单号、清空物料输入框
  │                          └─ loadKeyComponentInfo(cb)
  │                                ├─ showLoading("加载关重件中...") → 对每张单各查一次关重件信息
  │                                ├─ 任一失败→clearKeyComponentState() + Toast「加载失败」
  │                                ├─ 全部成功→写 orderDataMap → mergeOrderData()（配置/序列号打归属、合并 removeSnList）
  │                                │        → renderKeyComponentList() → applyButtonSwitch()
  │                                └─ cb: 聚焦物料输入框（临时只读，不弹键盘）
  │  扫物料 + 回车 ───▶ handleMaterialCheck()
  │                     ├─ 在途锁？「正在提交，请稍候」
  │                     ├─ 有订单集合？
  │                     ├─ 有内容？→ 格式合法（3 段；第三段 `序列号[:数量[:其它]]`：不带数量按 1，带数量须纯正数，数量之后的段忽略）？
  │                     ├─ 是集合内关重件？（按 materialNo 匹配）
  │                     ├─ 序列号未采过？（state.serialList）
  │                     ├─ 物料类型还有待解绑？（removeSnList 按 materialID 或 materialNo 回查 keyComponentList 得到 materialType，同类型条数 > 0）→ 跳解绑页（带类型）
  │                     ├─ 归属订单：未满量单（改制优先 → 生产单）→ 都满走更换（改制单）
  │                     ├─ isReplace：生产单看该物料是否采完；改制单看采完 或 同 VIN 生产单该物料是否有已采 SN
  │                     ├─ 位置：按 §二「位置弹窗与序号来源」解析（自动分配 / 弹窗）
  │                     └─ buildPendingScan()（含归属订单 wipOrderNo/wipOrderType/vin）→ materialSeq 归一为 "1"/"2"/""
  │                          ├─ isReplace=否 → Save(oldGenealogyID="")
  │                          │     ├─ 失败→Toast「提交失败」+ pendingScan 清空
  │                          │     └─ 成功→Toast「采集成功」→ 刷新关重件信息 → 清空+聚焦输入框
  │                          └─ isReplace=是 → 移除旧件 + 保存新件（视图3，见序列 C）
```

### 序列 B：解绑（视图2）

```
点「解绑」/扫码触发 ─▶ enterRemoveView(materialType?)
              ├─ 头部写「改制订单号（改制订单）」+ 过滤提示（有类型时显示「仅显示「<类型>」的待解绑」）
              ├─ 列表：removeSnList 按 materialID 或 materialNo 回查 keyComponentList 的 materialType 过滤（内存数据，不请求；描述也取自 keyComponentList）
              │   卡片展示：订单号、物料编码、描述、旧序列号、位置（materialSeq，前/后电机）、录入时间
              └─ switchView("key-component-remove-view") → renderRemoveRecordList
点「移除」 ─▶ removeRecord(record) → 二次确认
              ├─ 移除关重件{ wipOrderNo, wipOrderType, vin, serialNo }（行内订单，可能非当前单）
              ├─ 失败→Toast「移除失败」
              └─ 成功→Toast「移除成功」→ 刷新关重件信息（removeSnList + 卡片）
                         ├─ 当前过滤类型待解绑归 0 → leaveRemoveView() 自动回视图1（保留二维码）
                         └─ 仍有待解绑 → renderRemoveRecordList() 重渲染，留在视图2
点「返回」 ─▶ backToCheckView()（无半完成状态）→ 视图1 + 刷新关重件信息
```

## 四、数据流与代码级细节

### 页面尺寸与宿主适配

| 函数 | 行为 |
|---|---|
| `compensateHostTopGap()` | 抵消宿主在根容器上方留下的不可见占位：先复位 `margin-top`，仅当父层无 `padding`/`border` 且「根容器顶部偏移 − 父层顶部偏移」∈ (0, 40] 时施加等量负 margin；本地直开 / iframe 下差值为 0 → no-op |
| `fitPageHeight()` | 容器高度 = 视口高 − 根容器顶部偏移（下限 240px），解决表单宿主无高度链导致的整页滚动条 |

> `initPage` 与 `resize` 都按 **先 `compensateHostTopGap()` → 再 `fitPageHeight()`** 的顺序执行（顺序反了高度会按旧偏移计算）。

> 页面顶部不再有自绘标题行（由框架自带标题栏展示）：「VIN更换」按钮作为根容器的**流式首项**贴顶右对齐（`align-self: flex-end` + `margin: 0 16px`，小屏 12px），按钮自身高度即顶部占用、顶部不留额外间距；按钮为实底白底，以便在浅色内容上可读。

### 一次换件的完整数据流

```

     → 物料类型待解绑检查        : removeSnList 按 materialID 或 materialNo 回查 keyComponentList → 同 materialType 条数 > 0 → 跳解绑页（带类型）
     → resolveScanOwner         : 归属订单（未满量单：改制优先 → 生产单；都满走更换）+ 该单配置
     → getMaterialQuantityState : { collectedQuantity, requiredQuantity }（按归属订单隔离）
     → resolveMaterialSequence  : materialSeq（位置弹窗人工选 / 页面自动分配 / 配置序号）
     → findComponentBySequence  : 对应配置条目（决定 materialID / uomCode）
     → buildPendingScan         : 本次扫描上下文（含归属订单 wipOrderNo/wipOrderType/vin、inputType/inputCode）
     → buildCheckReported       : 保存报文（正常采集 / 替换共用）
```

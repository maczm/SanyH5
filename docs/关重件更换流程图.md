# 关重件更换流程图（mom-key-component-change）

> 本文件只放流程图（用户操作流程 / 状态机 / 接口时序 / 数据流）。
> 约束与规则见 `../AGENT.md`（§13.3 业务约定）；接口协议见 `关重件更换INF.md`。
> 时序图中接口一律用语义名（对照 Portal 函数名见 §三 表头），不使用接口编号。

## 一、用户操作流程

### 流程 A：正常采集

```
① 订单号/VIN 输入框 → 扫码或键入 → 回车（或点 🔍）
        ↓  接口：查询订单信息 → 查询关重件信息
② 订单号后出现「（生产订单）/（改制订单）」标注；
   需采集数量出现 x/y；卡片按最近扫描时间列出
        ↓  自动聚焦「物料二维码」输入框
③ 扫关重件二维码 → 回车（或点 🔍 / 📷）
        ↓  需要定位置时，先在表单区「关重件序号」人工选 前电机/后电机（再点一次取消）
        ↓  页面校验：格式 → 是否本订单关重件 → 是否已采集 → 位置（人工选的优先）→ 是否满量
        ↓  永磁体同步电机：采集时序号配置不明确才弹位置选择；更换时必须弹位置选择
④ 采集成功：Toast「采集成功」，列表与数量自动刷新，输入框清空并保持聚焦
        ↓
⑤ 重复 ③ 直到「需采集数量」达到 x/x
⑥ 点「完成」→ 确认 → 会话清空，可开始下一单
```

### 流程 B：改制订单解绑（视图2）

```
① 改制订单查询成功后，「需解绑数量」显示 1/2 这类进度
② 点「解绑」→ 进入视图2，列出待移除明细（可能来自多张单，行内订单号带类型）
③ 点某行「移除」→ 确认 → 旧件被解绑，Toast「移除成功」
        ↓  页面自动刷新：关重件信息（进度、卡片）＋ 待移除清单
④ 重复 ③ 直到清单清空 / 进度达标
⑤ 点「返回」→ 回主页
```

### 流程 C：换件（视图3）

```
① 表单区先人工选「关重件序号」（前电机/后电机，可选；仅在不弹窗的场景生效）
② 扫到满量物料（或后台判定需更换：校验并保存扫描件 返回 isChange=1）
        ↓  永磁体同步电机必须弹位置选择（人工已选也要弹）；其他关重件不弹窗
③ 视图3 列出待更换旧件（按本次新件的物料编码 + 序号过滤：前电机只回前电机旧件）
④ 选一条旧件 → 点「更换」→ 确认
        ↓  页面执行：移除关重件 → 保存新关重件（materialSeq = 人工所选 "1"/"2"，其它情况 ""）→ 刷新关重件信息
⑤ 成功：Toast「更换成功」→ 自动回主页，数量保持不超过需采总数
```

## 二、状态机

### 视图状态机

> 图中「刷新数据」＝重新查询关重件信息，更新卡片与数量标签（含解绑进度）。

```
                 ┌──────────────────────────────┐
                 │ 视图1 更换主页                │
                 │ (.key-component-check-view)   │
                 └───┬───────────┬───────────┬───┘
      解绑按钮(改制且还需解绑)│   满量扫描/      │ 完成(二次确认)
                           │   isChange=1     │
                           ▼                  ▼
              ┌────────────────────┐   ┌────────────────────┐
              │ 视图2 移除页        │   │ 视图3 更换页        │
              │ 返回→视图1+刷新数据 │   │ 返回→(半完成则确认) │
              └────────────────────┘   │ →视图1+刷新数据     │
                                       └─────────┬──────────┘
                                       更换成功→视图1+刷新数据
```

### `pendingScan` 生命周期（换件的核心）

```
handleMaterialCheck()
   ├─ 未满量 → checkAndSave(): pendingScan = 本次扫描 → 校验并保存扫描件
   │        ├─ res.code !== 0        → pendingScan = null（可重新扫）
   │        ├─ isChange !== "1"      → pendingScan = null → 刷新关重件信息
   │        └─ isChange === "1"      → 保留 pendingScan → enterChangeView()
   └─ 已满量 → startMaterialChange(): pendingScan 为空才写入 → enterChangeView()
                                        （pendingScan 非空说明已在换件决策中，直接忽略重复触发）
视图3:
   移除关重件 成功 → changedOldGenealogyId / changedOldSerialNo 落库到 state，行标记「重试保存」
   保存新关重件 成功 → pendingScan / changedOldGenealogyId / changedOldSerialNo 全部清空
   保存新关重件 失败 → 三者保留（半完成态），允许「重试保存」
   返回（半完成）→ 二次确认 → leaveChangeState() 清空三者
```

### 序号人工选择与位置弹窗（`state.manualMaterialSeq`）

```
表单区点「前电机」/「后电机」 → 选中（"1"/"2"）；再点已选项 → 取消（""）
位置弹窗只对永磁体同步电机（materialType = "永磁体同步电机"）发生：
   采集：序号配置不明确（两条配置不是恰好 "1"+"2"）或前后位置都已采集 → 弹窗
         配置明确且有未采集位置 → 自动分配，不弹窗
   更换：必须弹窗，由操作员现场指定被替换的位置（表单区已预选也要弹）
其他关重件：一律不弹窗 → 直接取配置序号（单条取该条，多条取首条）
人工选择的生效范围：不弹窗的场景下优先于自动分配（该物料配置存在 "1"/"2" 时才生效）
序号行显隐：当前订单没有任何前后位置关重件时整行隐藏
上报归一：null/undefined → ""；其它配置值（如 "3"）原样上报
进入视图3 → 作为 查询待更换明细 的 materialSeq 入参（"" 表示不按位置过滤）
「完成」重置会话 → 清空选择
```

## 三、接口调用时序

> 语义名 ↔ Portal 注入函数对照（字段级协议见 `关重件更换INF.md`）

| 语义名 | window 函数 | taskType |
|---|---|---|
| 查询订单信息 | `KeyComponentChange_GetWipOrderNoInfo` | `GetWipOrderNoInfo` |
| 查询关重件信息 | `KeyComponentChange_GetKeyComponentInfo` | `GetKeyComponentInfo` |
| 校验并保存扫描件 | `KeyComponentChange_CheckAndSave` | `CheckAndSave` |
| 移除关重件 | `KeyComponentChange_Remove` | `Remove` |

### 序列 A：查单 + 正常采集

```
操作员                页面                        Portal 注入函数
  │  输入/扫码订单 ───▶ queryOrderInfo()
  │                     ├─ 解析：纯数字→wipOrderNo；17位非纯数字→vin；其它→wipOrderNo
  │                     ├─ showLoading("查询订单中...")
  │                     ├─ 查询订单信息 ─────────▶ KeyComponentChange_GetWipOrderNoInfo
  │                     │   （序号守卫：过期响应丢弃）
  │                     ├─ hideLoading
  │                     ├─ 失败→Toast「查询失败」+ 画面保持上一单（orderInfo 不变，数据自洽）
  │                     └─ 成功→state.orderInfo = data
  │                          ├─ clearKeyComponentState()   ← 换单即清空上一单关重件数据
  │                          ├─ 订单号标签带类型标注、清空物料输入框
  │                          └─ loadKeyComponentInfo(cb)
  │                                ├─ showLoading("加载关重件中...") → 查询关重件信息
  │                                ├─ 失败→clearKeyComponentState() + Toast「加载失败」
  │                                ├─ 成功→写入 keyComponentList/serialList/removeQty/needRemoveQty
  │                                │        → renderKeyComponentList() → applyButtonSwitch()
  │                                └─ cb: 聚焦物料输入框（临时只读，不弹键盘）
  │  扫物料 + 回车 ───▶ handleMaterialCheck()
  │                     ├─ 在途锁？「正在提交，请稍候」
  │                     ├─ 有订单？→ 有内容？→ 格式合法（3段/非空/数量纯正数）？
  │                     ├─ 是本订单关重件？（按 materialNo 匹配配置）
  │                     ├─ 序列号未采过？（state.serialList）
  │                     ├─ 满量判定：已采条数 ≥ Σ materialQty ?
  │                     ├─ 位置：仅永磁体同步电机可能弹窗
  │                     │    采集：配置明确（两条恰好 1+2）且有未采集位置 → 自动分配（人工已选则听人工的）
  │                     │    采集：配置不明确 / 前后位置都已采集 → 弹窗
  │                     │    更换：必须弹窗（人工已选也要弹）
  │                     │    其他关重件：不弹窗 → 取配置序号（单条取该条，多条取首条）
  │                     └─ buildPendingScan() → materialSeq 归一为 "1"/"2"/""
  │                          ├─ 未满量 → 校验并保存扫描件
  │                          │     ├─ 失败→Toast「提交失败」+ pendingScan 清空
  │                          │     ├─ isChange==="1"→ 进视图3
  │                          │     └─ 其它→Toast「采集成功」→ 刷新关重件信息 → 清空+聚焦输入框
  │                          └─ 已满量 → 移除旧件 + 保存新件（视图3，见序列 C）
```

### 序列 B：解绑（视图2）

```
点「解绑」 ─▶ enterRemoveView()
              ├─ 头部写「改制订单号（改制订单）」
              ├─ switchView("key-component-remove-view")
              └─ loadRemoveRecordList() → 查询待移除明细 → renderRemoveRecordList → applyButtonSwitch
点「移除」 ─▶ removeRecord(record) → 二次确认
              ├─ 移除关重件{ wipOrderNo, wipOrderType, serialNo, materialSerialNo }（行内订单，可能非当前单）
              ├─ 失败→Toast「移除失败」
              └─ 成功→Toast「移除成功」→ 刷新关重件信息（进度+卡片） + 刷新待移除清单
点「返回」 ─▶ backToCheckView()（无半完成状态）→ 视图1 + 刷新关重件信息
```

### 序列 C：换件（视图3，含失败重试）

```
① 进入：满量扫描 / 校验并保存扫描件 返回 isChange=1
   enterChangeView()
     ├─ 头部：订单号-物料编码-物料描述 / 新序列号
     ├─ switchView("key-component-change-view")
     └─ loadChangeRecordList() → 查询待更换明细{ wipOrderNo, wipOrderType, materialNo,
                                                materialSeq } → 渲染明细
                                  （materialSeq 取位置弹窗/人工选择："1"/"2" 时后台只回该位置旧件，"" 不按位置过滤）

② 首次更换：点某行「更换」→ 二次确认「确认将旧序列号 X 更换为 Y ？」
     ├─ 移除关重件{ 行内 wipOrderNo/serialNo, record.materialSerialNo }
     │    ├─ 失败 → Toast「移除失败」，无残留状态，可重选
     │    └─ 成功 → state.changedOldGenealogyId = data.oldGenealogyID
     │              state.changedOldSerialNo = record.materialSerialNo
     │              markChangeRecordPendingSave()   ← 该行变淡 + 按钮文案「重试保存」
     │              loadKeyComponentInfo()          ← 先刷新关重件信息（请求序号 N）
     │              saveChangedKeyComponent()       ← 紧接着 保存新关重件（请求序号 N+1）
     │                   ├─ 失败 → Toast「移除成功，保存失败，请重试」；保留三者，停留视图3
     │                   └─ 成功 → 清 pendingScan/changedOld* → Toast「更换成功」
     │                            switchView(视图1) → 刷新关重件信息 → 清空并聚焦输入框

③ 重试（半完成态）：
     点「重试保存」（同一行） ─▶ 命中 changedOldGenealogyId 且序列号一致
                                  → saveChangedKeyComponent()：只发 保存新关重件（**不再移除旧件**）
     点其它行「更换」         ─▶ 拦截 + Toast「旧件 X 已移除但新件未保存，请点「重试保存」」
     点「返回」               ─▶ 二次确认「…返回将丢失本次更换，是否继续？」
                                  ├─ 取消 → 留在视图3，状态不变
                                  └─ 确定 → leaveChangeState() → 视图1 + 刷新关重件信息

④ 竞态保护：② 中两次「刷新关重件信息」重叠时（先发序号 N、后发序号 N+1），序号守卫保证
   只有 N+1 的结果会渲染；慢回的旧数据（不含新件、且含已置换旧件）不会覆盖界面。
```

## 四、数据流

### 一次换件的完整数据流（备忘）

```
扫码 → parseMaterialQrCode      : { materialNo, partner, materialSerialNo, materialQty }
     → findMatchedComponents    : 配置条目[]
     → getMaterialQuantityState : { collectedQuantity, requiredQuantity }
     → 序号（表单区人工选）      : "1"/"2" —— 选中且该物料有前后位置时优先，覆盖自动分配与弹窗
     → resolveMaterialSequence  : 未选时的 materialSeq（自动分配 / 弹窗）
     → findComponentBySequence  : 对应配置条目（决定 materialID / uomCode）
     → buildPendingScan         : 本次扫描上下文（含 inputType/inputCode）
     → buildCheckReported       : 「校验并保存扫描件」「保存新关重件」共用报文
                                  = 订单物料 + 关重件 + 二维码 + 输入方式
     → 移除关重件 → oldGenealogyID : 被替换旧件 ID
     → 保存新关重件(reported + oldGenealogyID) → 刷新关重件信息 → 会话回到视图1
```

## 五、更换流程逐帧拆解

### 5.1 两条入口（差异只在"谁触发更换判定"）

| 入口 | 触发条件 | 是否调用校验并保存扫描件 | `materialSeq` 来源 | `pendingScan` 写入点 |
|---|---|---|---|---|
| **A 满量扫描** | 该物料已采条数 ≥ 该物料 Σ`materialQty` | **不调用** | 永磁体同步电机更换必弹位置选择；其他关重件取配置序号 | `startMaterialChange()` |
| **B 后台判定** | 校验并保存扫描件 返回 `data.isChange === "1"` | 调用 | 同上，**位置确定发生在该调用之前** | `checkAndSave()` |

### 5.2 帧表（函数级）

| 帧 | 触发 | 执行函数 | state 变化 | 界面变化 | 接口（语义名） |
|---|---|---|---|---|---|
| F0 | 物料框回车 / 🔍 / 📷 | `setInputSource` → `handleMaterialCheck` | `inputSource` = 手输13 / 手输1 / 扫码1 | — | — |
| F1 | 六道校验门 | 在途锁 → 有订单 → 有内容 → 格式 → 本单关重件 → 未采过 | 无 | 失败 Toast，**输入框保留原值** | — |
| F2 | 满量判定 | `getMaterialQuantityState` | 无 | — | — |
| F3 | 位置解析 | `resolveMaterialSequence`（内含人工选择优先） | 无 | 永磁体同步电机：采集配置不明确/位置用尽才弹窗、更换必弹窗；其他关重件不弹窗 | — |
| F4 | 组装本次扫描 | `findComponentBySequence` → `buildPendingScan` | `pendingScan` = 上下文对象（`materialSeq` 归一为 `"1"`/`"2"`/`""`） | — | — |
| F5 | 分流 | A：`startMaterialChange`／B：`checkAndSave` → `submitCheckAndSave` | B：`isSubmitting=true` | B：Loading「提交中...」 | B：**校验并保存扫描件** |
| F6 | 进入视图3 | `enterChangeView` | `pendingScan` 保留 | 头部「订单-物料编码-描述」+「新序列号」；切视图3 | **查询待更换明细（带 `materialSeq`）** |
| F7 | 渲染清单 | `renderChangeRecordList` → `applyButtonSwitch` | 无 | 待更换明细卡 / 空态 | — |
| F8 | 点某行「更换」 | `changeRecord`（半完成守卫） | 无 | 二次确认「确认将旧序列号 X 更换为 Y ？」 | — |
| F9 | 确认 | `changeRecord` 内回调 | `changedOldGenealogyId`、`changedOldSerialNo` 落库 | 该行变淡 + 按钮文案「重试保存」；Loading「移除旧件中...」 | **移除关重件** → **刷新关重件信息** |
| F10 | 保存新件 | `saveChangedKeyComponent` | 成功：三者清空；失败：三者保留 | 成功 Toast「更换成功」→ 视图1；失败 Toast「移除成功，保存失败，请重试」 | **保存新关重件** |
| F11 | 重试（半完成态） | `changeRecord` 守卫 → `saveChangedKeyComponent` | `isSubmitting` 置位/复位 | 停留视图3，Loading「保存新件中...」 | **保存新关重件（不再移除旧件）** |
| F12 | 返回 | `backToCheckView` → `leaveChangeState` | 半完成先二次确认；确认后清 `pendingScan`/`changedOld*`/`isSubmitting` | 切视图1 | **刷新关重件信息** → `clearMaterialInput` |
| F13 | 收尾 | `loadKeyComponentInfo` 回调 | 写入新 `keyComponentList`/`serialList` | 数量与卡片刷新；输入框清空并聚焦 | — |

### 5.4 分支 → 终端状态

| 入口 | 位置选择 | 移除关重件 | 保存新关重件 | 用户动作 | 终端状态 |
|---|---|---|---|---|---|
| A 满量 | 自动 / 人工 | — | — | 点「返回」 | 回视图1，**本次新件不入库**，输入框清空 |
| A/B | — | 失败 | — | — | 停留视图3，`changedOld*` 未写入，可重选旧件 |
| A/B | — | 成功 | 成功 | — | 回视图1，三者清空，刷新关重件信息 |
| A/B | — | 成功 | 失败 | 同行「重试保存」 | 只重发保存新件，成功即收尾 |
| A/B | — | 成功 | 失败 | 改选其它行 | **被拦截**，提示先重试保存 |

### 5.5 竞态窗口与保护

| 窗口 | 风险 | 现有保护 |
|---|---|---|
| F0 连按回车（未满量） | 重复提交扫描件、重复入库 | `isSubmitting` 在途锁 |
| F0 连按回车（满量） | 重复进入视图3、拉两份待更换清单 | `startMaterialChange` 检查 `pendingScan` 非空即返回 |
| F0 连按回车（满量+需选位置） | 弹窗被重建（`on-pick` 被覆盖） | 无副作用：仍是同一次扫描，选中后只进一次视图3 |
| F9 → F10 之间 | 两次刷新关重件信息乱序回包覆盖新件 | `keyComponentRequestSequence` 丢弃过期响应 |
| F10 半完成态 | 改选其它旧件导致"新件挂错旧件" | `changedOldGenealogyId` + `changedOldSerialNo` 双重判定 |
| F12 | 误点返回静默丢弃换件 | 半完成态二次确认 |
| 换件途中切单 | 旧单数据被当作新单提交 | 查询订单信息 成功后清态；查询关重件信息 失败同样清空 |

### 5.6 边界与待确认

| # | 现状 | 触发 | 影响 |
|---|---|---|---|
| 1 | **移除关重件 返回 `code:0` 但 `data.oldGenealogyID` 为空** | 后台未回传 ID | `changedOldGenealogyId` 为 `undefined`（falsy）→ 半完成守卫不生效：此时改选其它旧件会再次移除，第一件成为"已移除未保存"（**待确认是否加固**） |
| 2 | 待更换清单为空 | 该物料无待更换旧件 | 只能「返回」，本次满量扫描作废（输入框被清空） |
| 3 | 视图3 清单不随移除结果刷新 | 保存失败后 | 已移除的旧件行仍在列表（以「重试保存」标记缓解） |
| 4 | 待移除 / 待更换明细无请求序号保护 | 返回后立刻重进 | 过期清单可能回填（概率低） |
| 5 | Mock 的待更换明细接口忽略 `materialNo` | 本地联调 | 本地清单不按物料过滤，与生产不一致（仅 Mock 行为） |

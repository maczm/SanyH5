# 关重件更换流程图（mom-key-component-change）

> 本文件只放流程图（用户操作流程 / 状态机 / 接口时序 / 数据流 / 代码级细节）。
> 约束与规则见 `../AGENT.md`（§8、§12）；接口字段协议见 `关重件更换INF.md`。
> 接口一律用语义名，对照 Portal 函数名见 §三 表头。

## 一、用户操作流程

### 流程 A：正常采集

```
① 订单号/VIN 输入框：输入/扫码自动转大写 → 回车（或点 🔍）
        ↓  接口：查询订单信息 → 查询关重件信息
② 订单号后出现「（生产订单）/（改制订单）」标注；
   需采集数量出现 x/y；卡片按最近扫描时间列出
        ↓  自动聚焦「物料二维码」输入框
③ 扫关重件二维码（输入/扫码自动转大写）→ 回车（或点 🔍 / 📷）
        ↓  页面校验：格式 → 是否本订单关重件 → 是否已采集 → 位置（见 §二）→ 是否满量
        ↓  永磁体同步电机：采集时序号配置不明确才弹位置选择；其他关重件取配置序号、不弹窗
④ 采集成功：Toast「采集成功」，列表与数量自动刷新，输入框清空并保持聚焦
        ↓
⑤ 重复 ③ 直到「需采集数量」达到 x/x
⑥ 点「完成」→ 确认 → 会话清空，可开始下一单
```

### 流程 B：改制订单解绑（视图2）

```
① 改制订单查询成功后，「需解绑数量」显示 1/2 这类进度
② 点「解绑」→ 进入视图2，列出待移除明细（可能来自多张单，行内订单号带类型）
③ 点某行「移除」→ 确认 → 旧件被解绑，Toast「移除成功」
        ↓  页面自动刷新：关重件信息（进度、卡片）＋ 待移除清单
④ 重复 ③ 直到清单清空 / 进度达标
⑤ 点「返回」→ 回主页
```

### 流程 C：换件（视图3）

```
① 扫到满量物料（或后台判定需更换：校验并保存扫描件 返回 isChange=1）
        ↓  永磁体同步电机必须弹位置选择（操作员现场指定前/后）；其他关重件不弹窗
② 视图3 列出待更换旧件（按本次新件的物料编码 + 序号过滤：前电机只回前电机旧件）
③ 选一条旧件 → 点「更换」→ 确认
        ↓  页面执行：移除关重件 → 保存新关重件（materialSeq = 所选 "1"/"2"，其它情况 ""）→ 刷新关重件信息
④ 成功：Toast「更换成功」→ 自动回主页，数量保持不超过需采总数
```

### 流程 D：VIN更换（视图4）

```
① 点右上角悬浮按钮「VIN更换」（不随表头显隐，四个视图下都可点）
        ↓  进入视图4：订单号预填当前订单号；旧VIN/新VIN/出厂编码清空；提示信息为前端固定文案
        ↓  查询 VIN 信息{ wipOrderNo } → 回填 旧VIN（标签）、旧出厂编码（预填出厂编码输入框供修改）（无当前订单则不自动查）
② 订单号输入框：输入/扫码自动转大写；回车 / 🔍 按钮 → 重新查询 VIN 信息；📷 按钮 → OpenCamera 扫码后自动查询
③ 新VIN、出厂编码输入框：输入/扫码自动转大写；📷 按钮扫码录入（也可手输）
④ 点「确认」→ 去除新VIN/出厂编码中的全部空格并回写输入框 → 校验：
        订单号非空 → 旧VIN 已查到 → 新VIN 非空且 17 位 → 出厂编码 非空且 16 位 → 新VIN 与出厂编码后五位一致
        ↓  保存 VIN{ wipOrderNo, oldVin, newVin, oldFactoryCode, factoryCode }（旧值来自查询，新值来自本次录入）
        ↓  成功：Toast「VIN更换成功」→ 自动回视图1（刷新关重件信息）
⑤ 点「返回」→ 回视图1（不调接口）
```

> 该按钮同样受 `BUTTON_SWITCH.vinChange` 显示/权限开关管辖（AGENT.md §8.11），开关项 `vinChange`；视图4 内每个按钮也有独立开关项。

### 无权限按钮的点击提示

| 按钮 | 开关项 | `permitted: false` 时点击 |
|---|---|---|
| 序列号行内「删除」 | `deleteSerial` | Toast「没有权限，请扫码更换」，不执行删除 |
| 右上角「VIN更换」 | `vinChange` | Toast「没有权限」，不进入 VIN更换 页面 |

> 这两项用 `.disabled` 类 + `aria-disabled` 做视觉禁用（开关项配了 `deniedMessage`），**不加原生 `disabled`**——原生 disabled 不派发 click，提示无从触发；其余按钮仍是原生 disabled。规则见 AGENT.md §8.11。

### 临时隐藏的按钮（扫码 API 待修复）

| 按钮 | 开关项 | 现状 |
|---|---|---|
| 物料二维码 📷 扫码按钮 | `scanMaterial` | `visible: false` 默认隐藏：扫码 API（`OpenCamera`）待修复，当前用 PDA 键入物料二维码后按回车/🔍；修复后将开关置回 `visible: true` 即恢复显示 |

> 隐藏只作用于 📷 按钮本身，物料二维码输入框、🔍 搜索按钮与 PDA 键入扫码链路均不受影响（回车/搜索/扫码三个业务入口中「扫码」由 PDA 键入承担）。

## 二、状态机

### 视图状态机

> 图中「刷新数据」＝重新查询关重件信息，更新卡片与数量标签（含解绑进度）；回到视图1 收尾统一为「刷新数据 + `clearMaterialInput()` + 聚焦输入框」。

```
                 ┌──────────────────────────────┐
                 │ 视图1 更换主页                │
                 │ (.key-component-check-view)   │
                 └───┬───────────┬───────────┬───┘
      解绑按钮(改制且还需解绑)│   满量扫描/      │ 完成(二次确认)
                           │   isChange=1     │
                           ▼                  ▼
              ┌────────────────────┐   ┌────────────────────┐
              │ 视图2 移除页        │   │ 视图3 更换页        │
              │ 返回→视图1+刷新数据 │   │ 返回→(半完成则确认) │
              └────────────────────┘   │ →视图1+刷新数据     │
                                       └─────────┬──────────┘
                                       更换成功→视图1+刷新数据

  任意视图下点右上角悬浮「VIN更换」→ 视图4 VIN更换页
        (.key-component-vin-change-view)
        返回 → 视图1（不调接口）；确认成功 → 视图1 + 刷新数据
```

### 两条更换入口（差异只在"谁触发更换判定"）

| 入口 | 触发条件 | 是否调用校验并保存扫描件 | `materialSeq` 来源 | 首次 `pendingScan` 写入点 |
|---|---|---|---|---|
| **A 满量扫描** | 该物料已采条数 ≥ 该物料 Σ`materialQty` | **不调用** | 永磁体同步电机更换必弹位置选择；其他关重件取配置序号 | `startMaterialChange()` |
| **B 后台判定** | 校验并保存扫描件 返回 `data.isChange === "1"` | 调用 | 同上，**位置确定发生在该调用之前** | `checkAndSave()` |

### `pendingScan` 生命周期（换件的核心）

```
handleMaterialCheck()
   ├─ 未满量 → checkAndSave(): pendingScan = 本次扫描 → 校验并保存扫描件
   │        ├─ res.code !== 0        → pendingScan = null（可重新扫）
   │        ├─ isChange !== "1"      → pendingScan = null → 刷新关重件信息
   │        └─ isChange === "1"      → 保留 pendingScan → enterChangeView()
   └─ 已满量 → startMaterialChange(): pendingScan 为空才写入 → enterChangeView()
                                        （pendingScan 非空说明已在换件决策中，直接忽略重复触发）
视图3:
   移除关重件 成功 → changedOldGenealogyId / changedOldSerialNo 落库到 state，行标记「重试保存」
   保存新关重件 成功 → pendingScan / changedOldGenealogyId / changedOldSerialNo 全部清空
   保存新关重件 失败 → 三者保留（半完成态），允许「重试保存」
   返回（半完成）→ 二次确认 → leaveChangeState() 清空三者
```

### 位置弹窗与序号来源

```
序号只有一个来源：位置弹窗人工选择，或页面自动分配（无其他入口）
位置弹窗只对永磁体同步电机（materialType = "永磁体同步电机"）发生：
   采集：序号配置不明确（两条配置不是恰好 "1"+"2"）或前后位置都已采集 → 弹窗
         配置明确且有未采集位置 → 自动分配，不弹窗
   更换：必须弹窗，由操作员现场指定被替换的位置
其他关重件：一律不弹窗 → 直接取配置序号（单条取该条，多条取首条）
上报归一：null/undefined → ""；其它配置值（如 "3"）原样上报
进入视图3 → 作为 查询待更换明细 的 materialSeq 入参（"" 表示不按位置过滤）
```

## 三、接口调用时序

> 语义名 ↔ Portal 注入函数对照（字段级协议见 `关重件更换INF.md`）

| 语义名 | window 函数 | taskType |
|---|---|---|
| 查询订单信息 | `KeyComponentChange_GetWipOrderNoInfo` | `GetWipOrderNoInfo` |
| 查询关重件信息 | `KeyComponentChange_GetKeyComponentInfo` | `GetKeyComponentInfo` |
| 校验并保存扫描件 | `KeyComponentChange_CheckAndSave` | `CheckAndSave` |
| 移除关重件 | `KeyComponentChange_Remove` | `Remove` |
| 查询待移除明细 | `KeyComponentChange_GetRemoveKeyComponentInfo` | `GetRemoveKeyComponentInfo` |
| 查询待更换明细 | `KeyComponentChange_GetChangeKeyComponentInfo` | `GetChangeKeyComponentInfo` |
| 保存新关重件 | `KeyComponentChange_Save` | `Save` |
| 查询 VIN 信息 | `KeyComponentChange_GetVinInfo` | `GetVinInfo` |
| 保存 VIN | `KeyComponentChange_SaveVin` | `SaveVin` |

### 序列 A：查单 + 正常采集

```
操作员                页面                        Portal 注入函数
  │  输入/扫码订单（自动转大写）─▶ queryOrderInfo()
  │                     ├─ 解析：纯数字→wipOrderNo；17位非纯数字→vin；其它→wipOrderNo
  │                     ├─ showLoading("查询订单中...")
  │                     ├─ 查询订单信息 ─────────▶ KeyComponentChange_GetWipOrderNoInfo
  │                     │   （序号守卫：过期响应丢弃）
  │                     ├─ hideLoading
  │                     ├─ 失败→Toast「查询失败」+ 画面保持上一单（orderInfo 不变，数据自洽）
  │                     └─ 成功→state.orderInfo = data
  │                          ├─ clearKeyComponentState()   ← 换单即清空上一单关重件数据
  │                          ├─ 订单号标签带类型标注、清空物料输入框
  │                          └─ loadKeyComponentInfo(cb)
  │                                ├─ showLoading("加载关重件中...") → 查询关重件信息
  │                                ├─ 失败→clearKeyComponentState() + Toast「加载失败」
  │                                ├─ 成功→写入 keyComponentList/serialList/removeQty/needRemoveQty
  │                                │        → renderKeyComponentList() → applyButtonSwitch()
  │                                └─ cb: 聚焦物料输入框（临时只读，不弹键盘）
  │  扫物料 + 回车 ───▶ handleMaterialCheck()
  │                     ├─ 在途锁？「正在提交，请稍候」
  │                     ├─ 有订单？→ 有内容？→ 格式合法（3段/非空/数量纯正数）？
  │                     ├─ 是本订单关重件？（按 materialNo 匹配配置）
  │                     ├─ 序列号未采过？（state.serialList）
  │                     ├─ 满量判定：已采条数 ≥ Σ materialQty ?
  │                     ├─ 位置：按 §二「位置弹窗与序号来源」解析（自动分配 / 弹窗）
  │                     └─ buildPendingScan() → materialSeq 归一为 "1"/"2"/""
  │                          ├─ 未满量 → 校验并保存扫描件
  │                          │     ├─ 失败→Toast「提交失败」+ pendingScan 清空
  │                          │     ├─ isChange==="1"→ 进视图3
  │                          │     └─ 其它→Toast「采集成功」→ 刷新关重件信息 → 清空+聚焦输入框
  │                          └─ 已满量 → 移除旧件 + 保存新件（视图3，见序列 C）
```

### 序列 B：解绑（视图2）

```
点「解绑」 ─▶ enterRemoveView()
              ├─ 头部写「改制订单号（改制订单）」
              ├─ switchView("key-component-remove-view")
              └─ loadRemoveRecordList() → 查询待移除明细 → renderRemoveRecordList → applyButtonSwitch
点「移除」 ─▶ removeRecord(record) → 二次确认
              ├─ 移除关重件{ wipOrderNo, wipOrderType, serialNo, materialSerialNo }（行内订单，可能非当前单）
              ├─ 失败→Toast「移除失败」
              └─ 成功→Toast「移除成功」→ 刷新关重件信息（进度+卡片） + 刷新待移除清单
点「返回」 ─▶ backToCheckView()（无半完成状态）→ 视图1 + 刷新关重件信息
```

### 序列 C：换件（视图3，含失败重试）

```
① 进入：满量扫描 / 校验并保存扫描件 返回 isChange=1
   enterChangeView()
     ├─ 头部：订单号-物料编码-物料描述 / 新序列号
     ├─ switchView("key-component-change-view")
     └─ loadChangeRecordList() → 查询待更换明细{ wipOrderNo, wipOrderType, materialNo,
                                                materialSeq } → 渲染明细
                                  （materialSeq 取位置弹窗或页面自动分配："1"/"2" 时后台只回该位置旧件，"" 不按位置过滤）

② 首次更换：点某行「更换」→ 二次确认「确认将旧序列号 X 更换为 Y ？」
     ├─ 移除关重件{ 行内 wipOrderNo/serialNo, record.materialSerialNo }
     │    ├─ 失败 → Toast「移除失败」，无残留状态，可重选
     │    └─ 成功 → state.changedOldGenealogyId = data.oldGenealogyID
     │              state.changedOldSerialNo = record.materialSerialNo
     │              markChangeRecordPendingSave()   ← 该行变淡 + 按钮文案「重试保存」
     │              loadKeyComponentInfo()          ← 先刷新关重件信息（请求序号 N）
     │              saveChangedKeyComponent()       ← 紧接着 保存新关重件（请求序号 N+1）
     │                   ├─ 失败 → Toast「移除成功，保存失败，请重试」；保留三者，停留视图3
     │                   └─ 成功 → 清 pendingScan/changedOld* → Toast「更换成功」
     │                            switchView(视图1) → 刷新关重件信息 → 清空并聚焦输入框

③ 重试（半完成态）：
     点「重试保存」（同一行） ─▶ 命中 changedOldGenealogyId 且序列号一致
                                  → saveChangedKeyComponent()：只发 保存新关重件（**不再移除旧件**）
     点其它行「更换」         ─▶ 拦截 + Toast「旧件 X 已移除但新件未保存，请点「重试保存」」
     点「返回」               ─▶ 二次确认「…返回将丢失本次更换，是否继续？」
                                  ├─ 取消 → 留在视图3，状态不变
                                  └─ 确定 → leaveChangeState() → 视图1 + 刷新关重件信息

④ 竞态保护：② 中两次「刷新关重件信息」重叠时（先发序号 N、后发序号 N+1），序号守卫保证
   只有 N+1 的结果会渲染；慢回的旧数据（不含新件、且含已置换旧件）不会覆盖界面。
```

### 序列 D：VIN更换（视图4）

```
点「VIN更换」 ─▶ enterVinChangeView()
                  ├─ 订单号 = 当前订单号（有当前订单时）；旧VIN/新VIN/出厂编码清空
                  ├─ 提示信息 = 前端固定文案
                  ├─ switchView("key-component-vin-change-view")
                  └─ 有当前订单 → queryVinInfo()（无当前订单则等操作员录入）

订单号输入框：输入/扫码自动转大写；回车 / 🔍 ─▶ queryVinInfo()
                  ├─ 空值 → Toast「请输入或扫码订单号」
                  ├─ 查询 VIN 信息{ wipOrderNo }（序号守卫：过期响应丢弃）
                  ├─ 失败 → Toast「查询失败」+ res.msg，旧VIN/旧出厂编码保持清空
                  └─ 成功 → 旧VIN = data.oldVin；旧出厂编码 = data.oldFactoryCode
                             两者落库 state（出厂编码输入框预填旧值并允许改写，提交时需回传原值）
订单号 📷 ─▶ OpenCamera → 回填订单号（转大写）→ queryVinInfo()
新VIN / 出厂编码：输入/扫码自动转大写；📷 ─▶ OpenCamera → 回填对应输入框（不调接口）

点「确认」 ─▶ saveVinChange()
                  ├─ 去空格并转大写：新VIN / 出厂编码 去除全部空白字符、转大写，并回写输入框
                  ├─ 校验：订单号非空 → 旧VIN 已查询 → 新VIN 非空且 17 位
                  │        → 出厂编码 非空且 16 位 → 新VIN 与出厂编码后五位一致（依次 Toast 拦截）
                  ├─ showLoading("提交中...") → 保存 VIN{ wipOrderNo, oldVin, newVin, oldFactoryCode, factoryCode }
                  ├─ 失败 → Toast「提交失败」+ res.msg，停留视图4
                  └─ 成功 → Toast「VIN更换成功」→ leaveVinChangeView() → 视图1 + 刷新关重件信息

点「返回」 ─▶ leaveVinChangeView()（清空输入与旧VIN）→ 视图1，不调接口、不刷新
```

## 四、数据流与代码级细节

### 页面配置（Portal 注入属性）

| 注入属性 | 页面行为 |
|---|---|
| `window.KeyComponentChangeHideHeader === true` | 隐藏 `.page-header`，根容器加 `header-hidden`（顶部留出悬浮按钮高度，按钮由半透明白换成实底白底以便在浅色内容上可读） |
| 缺省 / 非 `true` | 显示表头（默认形态） |

> 由 `applyHeaderVisibility()` 在 `initPage` 首步执行一次（AGENT.md §8.4：初始显隐状态必须在 `initPage` 显式执行）；表头隐藏**不影响**右上角悬浮的「VIN更换」按钮——两者互相独立。

### 一次换件的完整数据流

```
扫码 → parseMaterialQrCode      : { materialNo, partner, materialSerialNo, materialQty }
     → findMatchedComponents    : 配置条目[]
     → getMaterialQuantityState : { collectedQuantity, requiredQuantity }
     → resolveMaterialSequence  : materialSeq（位置弹窗人工选 / 页面自动分配 / 配置序号）
     → findComponentBySequence  : 对应配置条目（决定 materialID / uomCode）
     → buildPendingScan         : 本次扫描上下文（含 inputType/inputCode）
     → buildCheckReported       : 「校验并保存扫描件」「保存新关重件」共用报文
                                  = 订单物料 + 关重件 + 二维码 + 输入方式
     → 移除关重件 → oldGenealogyID : 被替换旧件 ID
     → 保存新关重件(reported + oldGenealogyID) → 刷新关重件信息 → 会话回到视图1
```

### 函数级帧表（触发/界面/接口见 §一 流程 A/C 与 §三 序列 A/C）

| 帧 | 执行函数 | state 变化 |
|---|---|---|
